# Pinned GPU motion interpolation sources

This directory retains the locally adapted Pinned motion core from [FongMi/mpv commit `f0ebca2a2c546444d9f9a62662b2f6e27614f7de`](https://github.com/FongMi/mpv/tree/f0ebca2a2c546444d9f9a62662b2f6e27614f7de/video/out/gpu_next). The upstream progress notes are at [`DOCS/memc-progress.md`](https://github.com/FongMi/mpv/blob/04e9d60470cfac3b407bc8bafcd54e2955e8f761/DOCS/memc-progress.md). Its files retain their LGPL-2.1-or-later SPDX notices; local changes added pre-analysis and caller-owned output-texture paths for the former Media3 integration.

This older helper snapshot is retained with its source attribution, but it is not linked into Native Media3 and is not copied into the MPV runtime. The experimental MPV runtime now builds the complete FongMi/mpv source at [`95ec8e929f8ad2f97c8415c486971493a0b408df`](https://github.com/FongMi/mpv/tree/95ec8e929f8ad2f97c8415c486971493a0b408df), matching the motion source pair recorded by MPVRx's `mpvlibAndroid` v1.1.8.2 renderer manifest. `scripts/mpvrx_motion_source.py` verifies the exact `motion.c`/`motion.h` hashes, the unchanged `mp_motion_create(..., 480)` analysis cap, and Android display-time presentation. No local app-owned motion shader patch is applied; the retained patcher and this helper snapshot are not build inputs. There is no supported legacy upstream/runtime revision for the standalone `patch_motion_artifact.py`: it is test-only for synthetic exact-anchor fixtures, and its CLI explicitly marks the active MPVRx pin `95ec8e929f8ad2f97c8415c486971493a0b408df` as unsupported. The optional policy-test `--source` path verifies only the exact runtime revision/hash and never invokes this legacy transformer. The upstream downsample still samples one value per analysis texel rather than averaging a 4×4 source footprint, so thin-contour aliasing and target-device quality/performance remain unverified. Pinned's GPL-2.0 attribution and full upstream `LICENSE.GPL` text remain preserved alongside all upstream per-file notices.

The oblique-aperture and boundary cases in `scripts/tests/pinned_motion_artifact_policy_test.py` exercise only synthetic inputs to that unsupported legacy transformer; they are not active-runtime or device coverage. Adding the old patcher to an active build merely to make that fixture run would replace the verified pinned runtime path with an unsupported one, so the review's request for active oblique coverage is not applicable to this retained code. Any future motion change must instead be tested against its exact supported runtime source and GPU path.

Keep this attribution and each source-file notice with the retained code. This branch remains experimental, unmerged, and unreleased.

# Decisions

- 2026-11-25: The Now Playing screen in audio/video mode is `ui/player/controls/AudioPlayerControls.kt` (AudioPaletteGlassScene wrapper) — NOT `ui/browser/music/MusicPlayerScreen.kt` (that one only serves the dedicated music activity). Three earlier "full-screen album art / hi-res badge" fixes landed in MusicPlayerScreen and never showed in the user's player. Music-player UI changes must go to AudioPlayerControls (portrait scene ~line 1740-2270); full-screen art gate reads `audioPreferences.audioFullScreenArt` + `isPortrait` + `albumArtBitmap != null`.
- 2026-11-24: MPV stats overlay is video-only via a positive gate: `declaredMediaKind() == DeclaredPlaybackMediaKind.VIDEO` in `MPVView.postInitOptions()` (was `isDefinitelyAudioOnly() != true`, which flashed the stats page over music items whose metadata wasn't loaded yet). `PlayerStatsChipOwnerTest.mpvViewRestoresStatsOncePerCoreLikeKnownGoodBuild` pins this line; update both together.
- Music player header format info (`MusicPlayerScreen.kt`) probes with the queue item's `sourceExtension` (not the URL path — Jellyfin/Navidrome stream URLs have none) and renders "N-bit float" via `Format_Profile`. Navidrome `stream.view` is called without `format=raw`, so servers may transcode; the LOSSLESS badge reflects source metadata, not delivered audio.
